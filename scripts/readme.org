* Hammerspoon

Hammerspoon shortcut notes are tracked in =./hammerspoon/docs/hammerspoon.md=.

=~/.hammerspoon/init.lua= points at =./hammerspoon/boot.lua=. Lua files in
=./hammerspoon/auto-load/= are loaded alphabetically.

Hammerspoon modal helpers support single-key bindings with =bind_v2= and
multi-key chords with =bind_v3=. See =./hammerspoon/docs/hammerspoon.md= for
the chord behavior and qView examples.

* Zsh plugins

Selected Zsh directories under =./zshlang/= can be structured as public plugins while remaining the local source of truth. Plugin entrypoint files named =*.plugin.zsh= should stay thin loaders; implementation should live in modular =*.zsh= files.

See =./docs/zsh_plugins.md= for layout conventions and generic plugin-manager notes.

* Pandoc conversion

[[agfi:pandoc-convert]] (=./zshlang/auto-load/others/pandoc.zsh=) is the single
gateway behind =md2org=, =org2md=, =html2org=, etc. Output fixups live as Lua
filters in =./python/pandoc_filters/= rather than as textual postprocessing, so
they cannot corrupt code/example blocks.

Known conversion problems and their filters are documented per-issue:

- =./docs/md2org-latex/readme.md= — LLM-style =\[...\]= math survives org's parser.
- =./docs/md2org-details.md= — =<details>=/=<summary>= folding, and pandoc's
  obsolete =#+begin_html= raw-HTML wrapper.
- =./docs/html2org-empty-underline.md= — stray =__= from Outlook emails.

=./docs/md-strip-german-lessons.md= covers the two functions that remove the
=Learning German ^_^= sections my LLM instructions append: the =md2org=-path
one for single answers, and the standalone one for conversation exports.

* Antigravity

=./docs/agy_status.md= covers =agy-status=, which reads the per-model-group
quota that =agy -p /usage= prints without spending any of it, and the

* Agent usage limits

=./docs/agent-usage-armed.md= covers the one-shot job shared by the Claude
Code, Codex and Antigravity notifiers: it waits in a tmux session for a reset
time and then either notifies or types =Continue.= into kitty windows, tmux
panes or a Codex queue chosen at arm time, unless you are at the keyboard.
Where each agent's reset time comes from, and the =cck= / =cct= / =ccfront=
entry points, are in =./docs/claude_code_usage.md=, =./docs/codex_status.md=
and =./docs/agy_status.md=; =agent-usage-continue-at= names the time by hand
for any agent, when there is no reset source or you do not trust the one there
is.
=agent-status= (=agst=) prints all three usage reports at once, in parallel.

=./docs/agent-auto-continue.md= covers =/auto-continue=, the skill shared by
all three agents that lets a session arm itself ahead of time: a watcher per
account polls the usage and, once it is blocked, arms the same job with the
registered sessions as targets, so they resume at the reset with nothing to
pick.

* Global npm installs

pnpm cannot install any package whose tarball is larger than roughly 50MB: it
hashes the tarball in a worker thread, where the structured clone has already
downgraded the =Buffer= to a plain =Uint8Array=, and Node stringifies those.
Both codex and claude-code are over that line, so [agfi:codex-install] and
[agfi:claude-install] go through npm. See =./docs/npm-global-installs.md=,
which also covers the orphaned npm staging directory that silently broke
reinstalls for eight months.

* Tailscale

=./docs/tailscale-setup.md=.

* Emacs terminal colors

=setup/terminfo-24bit.src= provides one truecolor definition for Kitty and
Termux. Installation and verification: =./docs/emacs-truecolor.md=.
=emc-mobile= opens a truecolor terminal frame with mobile line-number suppression.
Copies from these frames use Emacs's native OSC 52 support to reach the terminal
client's clipboard; limits and tmux setup are in =./docs/emacs-mobile-clipboard.md=.
The deferred receiver design is in =./.docs/plans/clipboard-listener.md=.
=emc-mobile-tmux= hosts that frame in a tmux session named =emacs-mobile=, so its
tty outlives the connection instead of dying with it, and reattaches to it later.

Under tmux the colors are re-encoded through the attached client's terminfo, so a
Termux client reporting =xterm-kitty= received a spelling it cannot parse and
printed the escapes as text. Cause and fix: =./docs/tmux-termux-truecolor.md=.

* Terminal titles

[agfi:tty-title] labels a kitty tab with what it is running. Inside tmux it
reached only the pane title: =set-titles= is off by default, so tmux never
forwarded it to the attached client. Cause and fix, along with a command
injection found in the same function: =./docs/tmux-tty-title.md=.

[agfi:codex-m] preserves the launcher's static =⚡<directory>= title to avoid repeated
Termux toasts from background sessions, while keeping animations inside Codex.
Explicit =-c tui.terminal_title= arguments override that launcher default; the
tradeoffs and Termux behavior are documented in =./docs/tmux-tty-title.md=.

* UNIX sockets

kitty's remote control, the Emacs server and the iTerm focus helper all bind a
socket under =$NIGHT_SOCKETS_DIR=, =~/.local/state= by default, and
emphatically not under =~/tmp=: that directory gets swept, and a socket deleted
from under a live listener cannot be restored at all. See
=./docs/unix-sockets.md=, which also covers why kitty in particular can then
only be fixed by restarting it.

* External display brightness

=brightness-get= / =-set= / =-inc= / =-dec= drive external monitors over DDC/CI,
not just the built-in panel, because IOKit cannot reach an external one at all.
Each display is routed to whichever backend can talk to it —
[[agfi:brightness-displays]] shows which — and a selector picks the display when
several are attached, defaulting to the main one.

=display-black-on= / =-off= / =-toggle= blank a display outright. That is not the
same as brightness 0: on a built-in panel IOKit really does cut the backlight,
but DDC luminance 0 leaves an external one visibly lit, so those get a zero gamma
table with the DDC levels floored underneath. hyper+shift+F1/F2 go through here.
F1 also locks the keyboard and mouse for as long as the screen is black, so a
brushed key cannot type into an unseen window or turn the brightness back up;
hyper+shift+F2 releases both, and so does [[agfi:display-black-off]], which
every unblack path runs through.

See =./docs/external-display-brightness.md=, which also records how often DDC
reads come back corrupt and what is done about it.

* Fill-in-the-middle completion

=alt+.= completes the line you are halfway through writing, sending the text
left of the cursor as the prefix and the text right of it as the suffix, and
inserting one line at the cursor. Codestral answers in about 0.3s;
[[agfi:fim-provider-select]] switches to DeepSeek when the output matters more
than the wait.

[[agfi:fim-get]] is the request on its own, in =zshlang/auto-load/others/fim.zsh=,
so it also works in a pipe or over brish. Only the widget and the bindings are
interactive-only, in =zshlang/interactive/auto-load/FIM.zsh=. The Emacs twin is
=night/fim-get= in =~[dom]/autoload/night-mistral-fim.el=; the two speak the same
body to the same providers and want changing together.

Inserting refetches the autosuggestion. Our widgets are named =zle-*= so
zsh-autosuggestions never sees the edit, and the suggestion computed for the
old line both paints the freshly inserted text in the suggestion colour and
stays acceptable: with =ec hello= suggesting =' world and then some'=,
completing to =ec hello world= and pressing right arrow gave =ec hello world
world and then some=.

The prefix is =${PREBUFFER}${LBUFFER}=, so a completion asked for inside a
continuation -- an unclosed quote, a =for= still waiting for its =done= -- sees
the lines you already typed rather than just the one you are on. The completion
itself is still capped at a line.

Status goes to =zle -M=, after a blank line so it cannot be read as part of the
command, and is told apart by symbols rather than colour: =❄= marks the line as
ours, then =⋯= in flight, =✓= inserted, =∅= nothing but nothing wrong, =✗=
failed. Not a colour because =zle -M= cannot carry one -- it visualises control
characters instead of emitting them -- and because the slot that *can*,
=POSTDISPLAY=, belongs to zsh-autosuggestions: right arrow and twelve other
widgets splice whatever sits there into the command line as real text.

Outside a terminal the same completion is on =hyper+shift+right= (and
=hyper+ctrl+right= for DeepSeek), from =hammerspoon/core/fim.lua=. It reads the
text around the cursor through the Accessibility API where the app exposes it,
and otherwise through a =shift+cmd+up= / =cmd+c= / =shift+cmd+down= / =cmd+c=
dance over the clipboard -- Purple Telegram's Qt draft box does not appear in
the accessibility tree at all, and kitty's is always empty. The completion
arrives as a ghost in an alert band: any key inserts it, =Esc= discards it,
=⇧Esc= puts it on the clipboard, and anything we could not paste lands there
too. Hyper and purple keys pass through the ghost untouched.

In kitty and Emacs the same chord posts =alt+.= instead, since both already have
a FIM of their own that knows the buffer better than the Accessibility API can.
=fimAppPolicy= holds that, keyed by bundle ID.

See =./docs/fim.md=, which records the things that cost real time (ZLE's
=BUFFER= and =CURSOR= are not bound inside a =zle -F= handler; cancelling a
request by process group takes the request that replaces it down too; and
=cat -v= renders a real ESC byte and a literal =^[= pair identically, so it
cannot be used to check any of this), and why =fim_strip_space_p= is off: the
leading space these models return is almost always the right one.
