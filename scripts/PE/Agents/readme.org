#+TITLE: Agents

Global instruction files for every coding agent, assembled from shared,
private, per-agent, per-host and machine-local parts by
[[agfi:agents-md-sync]].

* Why assembly, and not symlinks or imports

Symlinks give one file to one agent and nothing else: no per-host layer, no
machine-local layer.

Imports would give all of that, and Claude Code supports them
(=@~/path/to.md=, four hops deep, no approval prompt at user scope). Codex
does not: it reads one =AGENTS.md= and does not inline =@path= references
([[https://github.com/openai/codex/issues/17401][openai/codex#17401]] is the
open request for it). Its =@filename= is an interactive prompt-time reference,
something else entirely.

=~/.claude/rules/= is likewise Claude-only, so it is deliberately unused here.

Using imports for Claude and something else for Codex would make the local and
per-host layers reach some agents and silently not others. That is precisely
the failure this replaced: =~/.claude/VPS.md= and =~/.claude/instructions.md=
were symlinked into place for months while Claude Code, which reads only
=CLAUDE.md=, never loaded either. The speech-to-text instruction had never once
reached Claude.

Assembly works the same for every agent regardless of what it supports, today
or later. The cost is that the written files are artifacts: do not edit them,
and re-run the sync after changing a source. The launchers do that for you.

* Layout

Git-tracked, here:

- =AGENTS.md= --- the shared spine. Every agent, every host.
- =agent-claude.md=, =agent-codex.md=, =agent-antigravity.md=,
  =agent-claude-work.md= --- one agent, every
  host. The prefix is load-bearing: a bare =claude.md= is the same file as
  =CLAUDE.md= on a case-insensitive filesystem, so Claude Code discovered this
  source as a nested project memory and loaded the tier twice, on macOS only.
- =hosts/<hostname>.md= --- every agent, one host. Not created by the
  bootstrap: an empty one committed by accident is worse than none.
- =disabled/= --- parked, assembled into nothing. =VPS.md= lives here.

Git-tracked, private, in =${nightNotesPrivate}/configs/agents/=: the same
=AGENTS.md=, =agent-<name>.md= and =hosts/<hostname>.md= names. Nothing in the
public spine is sensitive; anything that is goes here instead.

Untracked, per machine, created empty by bootstrap stage =15-agents-md=:
=~/.agents.local.md= and =~/.<agent>.local.md=.

* Assembly order

Broad to narrow, so the last part to mention something wins:

#+begin_example
PE/Agents/AGENTS.md
notes/private/configs/agents/AGENTS.md
PE/Agents/agent-<name>.md
notes/private/configs/agents/agent-<name>.md
PE/Agents/hosts/<host>.md
notes/private/configs/agents/hosts/<host>.md
~/.agents.local.md
~/.<agent>.local.md
#+end_example

Missing parts are normal and skipped. Empty ones are skipped too, so an
untouched local file costs nothing.

An *overlay* target assembles only the agent's own tiers:

#+begin_example
PE/Agents/agent-<name>.md
notes/private/configs/agents/agent-<name>.md
~/.<name>.local.md
#+end_example

The spine, the host tier and =~/.agents.local.md= are left out, because an
overlay is a second profile of an agent that already receives those by another
route. When every one of its tiers is empty the overlay assembles to nothing,
and the sync writes no file at all --- removing a stale one if it finds it.
A file holding only the provenance comment would be noise, and a leftover one
would be a lie.

* Targets

- claude --- =~/.claude/CLAUDE.md= (Claude Code reads =CLAUDE.md=, never
  =AGENTS.md=)
- codex --- =~/.codex/AGENTS.md=
- antigravity --- =~/.gemini/GEMINI.md=. The binary is =agy=; its state lives
  under =~/.gemini/antigravity-cli/=, and
  [[https://antigravity.google/docs/rules-workflows][the rules documentation]]
  puts its global rules in =GEMINI.md= there. A *global* =AGENTS.md= is read by
  nothing: for Antigravity that name is workspace-scoped only, alongside
  =.agents/rules/=.

- claude-work --- =~/.claude-work/CLAUDE.md=, an *overlay*. See
  [[agfi:claude-work]]: a second config home, so a second account, and Claude
  Code takes its user memory from =$CLAUDE_CONFIG_DIR/CLAUDE.md=.

  The spine is deliberately not written there. Claude Code also walks every
  ancestor of the session's cwd looking for =<dir>/CLAUDE.md= and
  =<dir>/.claude/CLAUDE.md=, and =$HOME= is an ancestor of every project here,
  so =~/.claude/CLAUDE.md= already loads --- as *project* memory. Under
  =~/.claude= itself that pickup is deduplicated against the user-tier file;
  in a second profile there is nothing to dedup against, so assembling the
  spine again would carry all of it twice.

  The cost of leaning on that is a real one, and worth stating rather than
  discovering: the spine reaches a work session only while its cwd is under
  =$HOME=. Started in =/tmp= or =/Volumes=, such a session gets the overlay
  alone. =agents-md-doctor= prints the dependency on every run.

gapcode is commented out of the list: it is not in use, and
=~/.gapcode/AGENTS.md= is left wherever the last assembly put it.

An agent whose directory does not exist on this host is skipped, so the same
sync runs everywhere.

Getting that target right took two corrections. =~/.gemini/= is shared with
Google's separate =@google/gemini-cli=, whose binary really is =gemini=, and a
directory name plus a content-farm search result is not evidence of what reads
what. Check the vendor's own documentation, and the installed binary, before
wiring a path.

* Usage

#+begin_src zsh :eval never
agents-md-sync     #: rebuild every agent's file; the launchers call this
agents-md-doctor   #: what each agent loads, and whether it is current
#+end_src

The launchers --- [[agfi:claude]], [[agfi:codex-m]], [[agfi:antigravity-m]]
--- call [[agfi:h-agents-md-sync-ask]], so the files are current whenever an
agent starts. One sync rewrites every agent's file, not just the caller's, so
any launcher keeps all of them current. It only writes when the content
actually changed, and is cheap enough for a hot path.

When the assembly fails --- an unreadable source, a half-synced notes clone
--- the wrapper prints the error and asks whether to launch anyway, defaulting
to no. Aborting outright would make a permissions glitch cost you the session;
continuing silently is how the old symlink arrangement went unnoticed for
months. With no tty to ask, it says so and continues.

=agents-md-doctor= exists because the failure mode is silence. It lists every
source, whether it exists and how long it is, then reports =STALE= if the
written file has drifted, =MISSING= if it was never written, and =OVERSIZED=
past 200 lines, which is where Claude Code's docs say adherence starts to drop.

Variables: =agents_md_dir=, =agents_md_private_dir=, =agents_md_host= override
the locations, and =agents_md_sync_verbose_p=y= makes the sync say what it
wrote.
