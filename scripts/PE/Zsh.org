Zsh Coding Guidelines:

- Always use long option/argument forms for CLI commands. This makes the code more readable.

- Use =gmv=, =gmkdir=, etc. when you want to use a GNU-specific feature, as the code must run on both macOS and Linux.

- Some basic functions/aliases are already defined, and should be used if needed:

#+begin_src :eval never
alias -g '@RET'=' || return $?'

function ec {
    #: `ec` should almost always be used instead of `echo`.
    print -r -- "$@"
}

function ecn {
    print -rn -- "$@"
}

function ecerr {
    ec "$@" >&2
}

function gquote {
    ec "${(qq@)@}"
}
alias gq=gquote

function reval {
    eval "$(gquote "$@")"
}

function bool {
    local i=$(echo "$1" | tr '[:upper:]' '[:lower:]')
    if [[ "${i}" == "n" ]] || [[ "${i}" == "no" ]] || [[ "${i}" == "0" ]]
    then
        return 1
    else
        test -n "${i}"
        return $?
    fi
}

function ensure-array {
    local i
    for i in $@ ; do
        if (( ${#${(P)i}} == 0 )) ; then
            typeset -ag "$i"
        fi
    done
}

function trs-rm {
    local paths=("$@")

    local p
    for p in $paths[@] ; do
        if test -e "$p" ; then
            reval-ec command rm -rf -- "$p"
        fi
    done
}
#+end_src

- Functions should be defined in the following form:

#+begin_src :eval never
function fn-name {
  ...
}
#+end_src

- All variables must be declared local unless global access is needed. Even for dependency injection, prefer:

#+begin_src :eval never
local dependency="${dependency:-default_value}"
#+end_src

All env vars (global vars) must be declared local as above, at the start of the function, so that the inputs of the functions are obvious at a glance.

When accessing a global var, we should simplify its local name, e.g.,:

#+begin_src :eval never
function bar {
  local flag_p="${bar_flag_p:-y}"
  ...
}
#+end_src

- Prefer keyword-style argument passing like the above, and keep positional arguments simple and intuitive to use.
- The global name of the keyword arguments should be namespaced to avoid potential conflicts. E.g., =bar_flag_p= above namespaces with =bar_=.
- The order of argument definition matters. E.g.,

#+begin_src :eval never
function ffmpeg-to-audio {
    ...
    local audio_extension="${ffmpeg_audio_extension:-m4a}"
    ...

    local input="${1}"
    local output="${2:-${input:r}.${audio_extension}}"
    ...
}
#+end_src

Notice how we need to first define =audio_extension=, then =output=.

- Do not use =~= in parameter-expansion defaults; it will not be expanded there. Prefer =${HOME}=:

#+begin_src :eval never
local config_path="${1:-${HOME}/example/config.yaml}"
#+end_src

- When the function needs to be passed an array, use this pattern:

#+begin_src :eval never
function ffmpeg-to-video {
    ...
    ensure-array ffmpeg_codec_opts
    local codec_opts=("${ffmpeg_codec_opts[@]}")
    ...
}
#+end_src

- All values should be quoted, including subshells:
#+begin_src zsh :eval never
some_var="$(some_command ...)"
#+end_src

However some values cannot be quoted:
#+begin_src zsh :eval never
functions["name"]="${body}"
#+end_src

This will actually define `"name"` as the function name, including the quotes.

- If we need to quote something that will be evaled later, we should use =gquote=.

- Note that these options are set:

#+begin_src :eval never
setopt multios re_match_pcre extendedglob
#+end_src

If you need to set an option or trap, be sure to use =setopt localoptions= or =setopt localtraps=.

- Use =in-or-args= variants idiomatically:
  - =in-or-args "$@"=: return text from args/stdin/clipboard.
  - =in-or-args2 "$@"=: populate =$inargs= (string) and =$in_or_args_in_p=.
  - =in-or-args3 "$@"=: populate =$inargs= as an array (line-split when reading stdin).
  - =in-or-args-pns "$@"=: newline-to-space mode.

- Write idiomatic Zsh. Prefer parameter expansion flags over external tools when practical (split/join/quote/etc), e.g. =${(@f)text}=, =${(j.\n.)arr}=, =${(qq)val}=.

- When in doubt between sed, awk, and perl, always use perl.

- Functions that take a source file and save an output file, should generally use an interface like this:

#+begin_src :eval never
function pdf-compress {
    local input="${1}"
    local out="${2:-${input:r}_compressed.pdf}"

    ...
}
#+end_src

- Function/command calls that might fail should use this pattern:
#+begin_src zsh :eval never
assert mkdir -p x/y @RET
#+end_src

=@RET= is already defined as:
#+begin_src zsh :eval never
alias -g '@RET'=' || return $?'
#+end_src

=assert= is also already defined, and can be treated as a version of =reval= defined above which just re-evaluates its input. The above pattern must only be used when the shell is NOT forking. For subshells, use the following pattern.

- For error handling subshells, use this pattern:
#+begin_src zsh :eval never
local tmp
tmp="$(gmktemp)" @TRET
#+end_src

=@TRET= is already defined as:
#+begin_src zsh :eval never
alias -g '@TRET'=' || { local retcode=$? ; ectrace_single_trace=y ectrace_ret=$retcode ectrace ; return $retcode }'
#+end_src

=@TRET= prints a detailed stacktrace. If the subshell is calling an embedded script with proper error reporting, then we can fall back to =@RET=:
#+begin_src bsh.dash :results verbatim :exports both :wrap results
local out
out="$(perl - "${tmp_file}" <<'EOF'
...
    print STDERR "Error: ...\n";
    exit 1;
...
EOF
)" @RET
#+end_src

- Some commands are okay to fail. You can use these two patterns to handle them:

This pattern ignores the error silently:
#+begin_src zsh :eval never
trs-rm some_temp_file || true
#+end_src

This pattern prints a stacktrace but ignores the error otherwise:
#+begin_src zsh :eval never
trs-rm some_big_file @STRUE
#+end_src

=@STRUE= is already defined:
#+begin_src zsh :eval never
alias -g '@STRUE'=' || { ectrace_single_trace=y ectrace_ret=$? ectrace ; true }'
#+end_src

Prefer silent errors when the error is inconsequential, like when deleting temporary files.

- When parsing structured input, use the appropriate tool with robust parsing, e.g., =jq= for JSON.

- Guard external dependencies at the top of the function, so a missing tool reports itself by name instead of failing somewhere deeper with a confusing error.

=isdefined-cmd= tests for a single command and prints nothing:
#+begin_src zsh :eval never
if isdefined-cmd bat ; then
    ...
fi
#+end_src

=ensure-cmd= takes one or more commands and fails with =missing command: X=:
#+begin_src zsh :eval never
function foo {
    ensure-cmd pandoc jq @RET
    ...
}
#+end_src

=ensure-dep1= additionally knows how to install what is missing. It checks, runs the install command, =rehash=es, then re-checks, so a fresh clone works on first use rather than after a separate setup step:
#+begin_src zsh :eval never
ensure-dep1 claude_session go-install-local "${NIGHTDIR}/golang/claude_session" @RET
#+end_src

Guard only what the current code path actually needs. E.g. a renderer that only shells out to =pandoc= for one output format should check for it inside that branch, not unconditionally:
#+begin_src zsh :eval never
if [[ "${format}" == org-pandoc ]] ; then
    ensure-cmd pandoc @RET
fi
#+end_src

Prefer =ensure-dep1= for things we build ourselves out of this repo (a local Go or Rust tool), and =ensure-cmd= for things the user is expected to install, since we should not silently install system packages on their behalf.

- The Go helper binary pattern: when a function's real work is better done in Go, it lives in =golang/<name>/= as its own module (=go.mod= with =module <name>=), with a =readme.org= documenting install and use, and tests as =*_test.go=.

zsh keeps the policy, Go does the work. The zsh side stays a thin wrapper that reuses the existing helpers, decides the fallbacks and formats the output; the binary is a pure computation/IO unit that emits JSON (or another parseable format) and takes no interactive decisions of its own.

Never check in a binary. Build on first use with an =h-<thing>-dep= guard, called from every wrapper that needs the tool:
#+begin_src zsh :eval never
function h-claude-code-session-dep {
    ensure-cmd go @RET
    ensure-dep1 claude_session go-install-local "${NIGHTDIR}/golang/claude_session" @RET
}
#+end_src

=ensure-dep1= only builds when the command is missing, and =rehash=es afterwards, so a fresh clone works on first use rather than after a separate setup step.

Keep these tools stdlib-only where you can, and pin an older =go= line in =go.mod= than the installed toolchain (ours use =go 1.21=) so =GOTOOLCHAIN= never tries to fetch one. Both keep =go install= working offline, which matters for any tool that may have to run before the network is up.

Most functions should stay in zsh. Reach for Go only when the shell is the wrong tool: genuine concurrency, typed errors or protocol control that =curl= exit codes only approximate, non-trivial parsing or data structures, or hot paths where repeated forking dominates.

- Heredocs must be used for long literal strings. E.g., when we are embedding a script.

- Helper/internal/private functions should be named =h-...=.

- When multiple implementations of a function are possible, name each implementation with a postfix. E.g., =pdf-compress-pdftk=, =pdf-compress-qpdf=. Then define a general gateway =aliasfn pdf-compres pdf-compress-qpdf=. This way, we can easily swap the default implementation used.

- DRY.

- Redis-stored variables:
#+begin_src zsh :eval never
function redis-defvar {
    local name="${1}"

    if test -z "${name}" ; then
        ecerr "$0: name not supplied"
        return 1
    fi

    fndef "${name}_get" redism get "$name"
    aliasfnq "${name}_set" silent redism set "$name"
    aliasfnq "${name}_setnx" silent redism setnx "$name"
    fndef "${name}_del" silent redism del "$name"
}
#+end_src

The above function can be used like this:
#+begin_src zsh :eval never
redis-defvar input_volume_cached

# To set it:
input_volume_cached_set "$vol"

# To set it if it does not exist:
input_volume_cached_setnx "$vol"

# To read it:
input_volume_cached_get

# To delete it:
input_volume_cached_del
#+end_src

The redis-backed variables should be used when some state needs to be shared between multiple shell instances.

- Stoppable background jobs (the =mark-me= pattern):

A job that has to be stopped from somewhere else — another shell, a keybinding, a hook — needs a name that survives the fork. =mark-me= gives it one by rewriting the subshell's own argv, so =pgrep= can find it again later:
#+begin_src zsh :eval never
function mark-me {
    local mark
    mark="$(marker-preprocess "$1")" @RET

    jobs -Z "zsh $mark $(gq "${@[2,-1]}")"

    typeset -g mark_current="$mark"
}
#+end_src

You rarely call it yourself: =awaysh-named= backgrounds a subshell, marks it, and evals the command inside it. =awaysh-bnamed= is the same thing in the brish garden, so the job outlives the terminal that started it.

The above can be used like this:
#+begin_src zsh :eval never
typeset -g SOME_JOB_MARKER='SOME_JOB_MARKER'

function h-some-job-loop {
    #: The loop body, as a function. See below for why.
    local dur="$1" sel="$2"
    assert-args dur sel @RET

    lo_s="$dur" loop some-job "$sel"
}

# To start it (one instance; restarting is how you change its arguments):
kill-marker "$SOME_JOB_MARKER" || true
awaysh-bnamed "$SOME_JOB_MARKER" h-some-job-loop "${lo_s:-5}" "$sel"

# To ask whether it is running:
silent pgrep -f "$SOME_JOB_MARKER"

# To stop it, and then undo whatever it was maintaining:
kill-marker "$SOME_JOB_MARKER" || true
some-job-cleanup
#+end_src

Four things that go wrong if you deviate:

  - The marker must be short. =mark-me= writes into the argv space the shell already reserved, and outside brish that is not much. =marker-preprocess= upcases it, turns =-= into =_=, and appends =_MARKER=, so =DBLACK_LOOP= and =DBLACK_LOOP_MARKER= name the same job.
  - The body must be a function. A bare builtin or simple command does not keep the marked subshell alive, and then there is nothing left carrying the marker.
  - Parameters travel as arguments, not in the environment. =awaysh-bnamed= crosses into the garden, which does not inherit our environment, and =gquote= would turn a =lo_s=5= word into a command name rather than an assignment.
  - Stop with =kill-marker=, never a hand-rolled =pkill -f=. =kill-marker= goes through =kill-withchildren=, which is what takes the =sleep= or =socat= that =loop= is currently blocked on down with the loop. Beware also that =pgrep -f= matches your own command line, so keep the marker out of it.

The cleanup belongs in the stopper, right after =kill-marker=, not in an =always= block inside the job: a killed process is not guaranteed to run one. =display-black-on-loop= / =display-black-off-loop= in =zshlang/auto-load/others/system.zsh= are the worked example.

Use this whenever a job must keep running until something else says stop. When you only need one instance of a job that quits on its own, =oneinstance-setup= is the lighter option.
